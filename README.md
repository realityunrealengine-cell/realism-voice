# Realism Voice

Десктопный мессенджер для Windows: серверы, текстовые и голосовые каналы, личные сообщения, друзья, видеозвонки и демонстрация экрана.

**Стек:** Electron 37 · React 18 + TypeScript · Vite 6 · Tailwind CSS · Zustand · Framer Motion · Lucide ·
Supabase (Auth, PostgreSQL + RLS, Realtime, Storage, Edge Functions) · Cloudflare Realtime SFU (WebRTC) · electron-builder + NSIS.

Всё работает через облако: ваш компьютер не нужно держать включённым, друзья подключаются из любой страны.

## ⬇️ Скачать

**[Последняя версия Realism Voice для Windows →](https://github.com/realityunrealengine-cell/realism-voice-releases/releases/latest)**

На странице релиза откройте раздел **Assets** и нажмите **`RealismVoice-Setup.exe`**. Дальше приложение обновляется само.
При первом запуске Windows SmartScreen может предупредить о неподписанном установщике: «Подробнее» → «Выполнить в любом случае».

## 2. Настройка Supabase (обязательно, один раз)

### 2.1. База данных — миграции

**Вариант А (проще): SQL Editor**
1. Откройте <https://supabase.com/dashboard/project/yqoxdrkxgnputpqsclzx/sql/new>.
2. Вставьте **всё** содержимое файла `supabase/setup.sql` и нажмите **Run**.
3. Скрипт идемпотентен — повторный запуск безопасен и не удаляет данные.

**Вариант Б: Supabase CLI**
```bash
npx supabase login
npx supabase link --project-ref yqoxdrkxgnputpqsclzx
npx supabase db push
```
(`link` спросит пароль базы данных — вводите его сами в терминале.)

Миграции создают: таблицы, индексы, ограничения, триггеры, RPC-функции, RLS-политики,
Storage-бакеты `avatars`, `server-icons`, `profile-banners`, `attachments` с политиками, публикацию Realtime и политики Realtime Authorization.

**Обновление существующей базы:** новую функцию можно применить отдельным файлом, не запуская всё заново. Для баннеров профилей
вставьте в SQL Editor содержимое `supabase/migrations/20261104000002_profile_banners.sql` и нажмите **Run**. Скрипт ничего не удаляет.
Для значка Tester так же примените `supabase/migrations/20261104000003_tester_badge.sql`.

**Вложения 1.1.0:** примените `supabase/migrations/20261107000001_attachments_v2.sql`. Скрипт ничего не удаляет и меняет
лимит только бакета `attachments` (25 → 50 МБ), аватарки, иконки и баннеры не затрагиваются. Квоты и использование —
`supabase/admin/attachment-limits.sql`. Подробнее — раздел 5а.

**Значки:** `owner` (единственный, золотой), `tester` (серебряный, можно выдавать нескольким), `null`. Значок только визуальный и привязан к id аккаунта.
Клиент изменить его не может. Выдача и отзыв — запросами из `supabase/admin/tester-badge.sql` в SQL Editor, по одному шагу.

### 2.2. Аутентификация — ссылки из писем

Authentication → **URL Configuration** → **Redirect URLs** → добавьте:
```
realismvoice://auth/callback
realismvoice://auth/reset
```
После этого ссылки «Подтвердить email» и «Сбросить пароль» из писем будут открывать Realism Voice.

Рекомендуется:
- **Authentication → Emails → SMTP Settings** — подключите свой SMTP. Встроенная почта Supabase отправляет лишь несколько писем в час и годится только для тестов.
- (необязательно) В шаблоны писем «Confirm signup» и «Reset password» добавьте `{{ .Token }}` — тогда в письме будет код, который можно ввести прямо в приложении, без перехода по ссылке.

### 2.3. Edge Function `voice-sfu`

**Через Dashboard:** Edge Functions → **Deploy a new function** → «Via Editor» → имя `voice-sfu` →
вставьте содержимое `supabase/functions/voice-sfu/index.ts` → Deploy.
Затем в настройках функции **выключите «Verify JWT with legacy secret»** — функция сама проверяет пользователя через `auth.getUser()` (это работает и с новыми ключами подписи JWT).

**Через CLI:**
```bash
npx supabase functions deploy voice-sfu --no-verify-jwt --project-ref yqoxdrkxgnputpqsclzx
```

Функция `livekit-token` (голос версий 1.1.x через LiveKit) больше не используется приложением 1.2.0+; её можно оставить для отката.

## 3. Настройка Cloudflare Realtime SFU (голос, видео, экран)

Медиа идут напрямую между приложением и Cloudflare Realtime SFU (WebRTC). Отдельный сервер не нужен:
Edge Function `voice-sfu` проверяет права и от имени пользователя вызывает API SFU, а состав комнаты
участники сообщают друг другу через уже существующие приватные каналы Supabase Realtime
(`typing:<канал>` — право как у просмотра канала, `dm:<переписка>` — только участники). База данных не меняется.

1. Cloudflare Dashboard → **Realtime → Serverless SFU → Create** (приложение, например `realism-voice`).
   Скопируйте **App ID** и **App Secret (API token)**.
2. Supabase Dashboard → **Edge Functions → Secrets** (Manage secrets) → добавьте:
   ```
   CF_SFU_APP_ID=<App ID>
   CF_SFU_APP_TOKEN=<App Secret>
   ```
   или через CLI:
   ```bash
   npx supabase secrets set CF_SFU_APP_ID=... CF_SFU_APP_TOKEN=... --project-ref yqoxdrkxgnputpqsclzx
   ```
3. Разверните функцию `voice-sfu` (раздел 2.3).

Необязательно: TURN Cloudflare для сетей, где закрыт UDP (Realtime → TURN → Create key) — секреты
`CF_TURN_KEY_ID` и `CF_TURN_KEY_API_TOKEN`. Без них используется STUN `stun.cloudflare.com`.

Ключи SFU **никогда** не попадают в приложение: ни в renderer, ни в preload, ни в переменные Vite, ни в GitHub.
Пока они не заданы, приложение честно показывает «Голосовой сервер Cloudflare Realtime не настроен», а не имитирует связь.

**Тарифы (проверено по документации Cloudflare):** первые 1 000 ГБ исходящего трафика Realtime (SFU и TURN вместе)
в месяц бесплатны, сверх — $0,05 за ГБ; входящий трафик (публикация) бесплатен. Ограничений по числу участников,
комнат или длительности приложение не вводит. Расход Realtime — одна строка в счёте Cloudflare (Billing).
Отдельной аналитики и уведомлений о расходе именно для SFU в документации Cloudflare нет (для TURN есть аналитика
через GraphQL API), поэтому расход стоит изредка проверять в разделе Billing.

**Реальная проверка связи:** создайте локальный файл `.env.sfu-test` (в `.gitignore`) с `CF_SFU_APP_ID=` и
`CF_SFU_APP_TOKEN=` и выполните `npm run test:sfu-live` — два участника в настоящем Chromium соединятся через
Cloudflare SFU и проверят звук, демонстрацию экрана, mute, восстановление и выход.

## 4а. Автообновления

Приложение проверяет `latest.yml` в GitHub Releases через 10 секунд после запуска и каждые 4 часа. Если есть новая версия,
у кнопки **«Обновления»** над панелью профиля появляется индикатор. В панели кнопка **«Обновить»** скачивает версию с настоящим процентом,
а **«Перезапустить и установить»** закрывает приложение, устанавливает обновление и запускает его снова.
Скачивать можно во время звонка, но установка во время звонка, демонстрации экрана или входящего вызова недоступна;
после звонка появляется предложение «Перезапустить и установить / Позже».
Выход из приложения и выключение Windows ничего не устанавливают (`autoInstallOnAppQuit = false`).
Журнал: `%APPDATA%\Realism Voice\logs\updater.log`.

Версия 1.0.2 не умеет обновляться сама: версию 1.0.3 нужно один раз поставить вручную поверх старой.
Данные сохраняются, потому что `appId` и папка `%APPDATA%\Realism Voice` не меняются.

### Настройка (один раз)

Исходники: публичный (только для просмотра) репозиторий `realityunrealengine-cell/realism-voice` (`origin`).
Обновления: публичный `realityunrealengine-cell/realism-voice-releases`, только установщики и `latest.yml`; приложение читает их без токена.
Секреты (токен релизов, ключ подписи обновлений, ключи Cloudflare Realtime SFU) хранятся только в GitHub Secrets и Supabase — в репозитории их нет.

1. Включите двухфакторную защиту GitHub.
2. Создайте Fine-grained token (**Settings → Developer settings → Personal access tokens**): доступ только к
   `realism-voice-releases`, **Repository permissions → Contents: Read and write**, срок до года.
3. В репозитории исходников, **Settings → Secrets and variables → Actions**:
   - Secrets: `RELEASES_GH_TOKEN` — токен из шага 2;
   - Secrets: `UPDATE_SIGNING_KEY` — всё содержимое `secrets/update-signing-key.pem` (ключ подписи манифестов);
   - Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, при необходимости `VITE_ENABLE_GOOGLE_AUTH`;
   - сертификат Windows: Secrets `CSC_LINK` и `CSC_KEY_PASSWORD` **или**, пока его нет, Variable `ALLOW_UNSIGNED_UPDATES=true`.

   Без этих настроек сборка остановится до начала работы, а без публичного ключа в `package.json` приложение обновления не примет.
4. Сохраните копию `secrets/update-signing-key.pem` в менеджере паролей. GitHub не показывает сохранённые секреты, а без этого ключа
   установленные приложения новых обновлений не примут. После этого файл можно удалить из папки проекта.
5. Проверьте настройку без релиза: **Actions → Dry run (build without release) → Run workflow**. Запуск проверит секреты, соберёт и подпишет установщик,
   загрузит файлы во временный черновик `dry-run-…` репозитория обновлений, сверит их и сразу удалит черновик.
   Пользователи его не видят, релиз и тег не создаются, опубликованные релизы не меняются. Установщик останется артефактом запуска.

### Выпуск версии

1. Опишите изменения в `build/release-notes.md`; в файле должен быть номер новой версии.
2. Закоммитьте их и поднимите версию, а затем отправьте тег:
   ```bash
   git add build/release-notes.md
   git commit -m "Описание версии"
   npm version patch
   git push --follow-tags
   ```
3. Workflow `.github/workflows/release.yml` проверит версию, TypeScript и RLS, соберёт установщик, подпишет `latest.yml`,
   сверит SHA-512 и подпись, загрузит все три файла в один черновик, проверит его состав и только тогда опубликует релиз.
   Пока идёт загрузка, пользователи обновление не видят. Уже опубликованный релиз workflow не меняет.

Постоянная ссылка для новых пользователей:
`https://github.com/realityunrealengine-cell/realism-voice-releases/releases/latest/download/RealismVoice-Setup.exe`.

Выпуск с ошибкой: снимите его с публикации или удалите в GitHub. Загруженную версию приложение больше не предложит,
но у тех, кто уже обновился, она останется: выпустите исправление с более высоким номером.

### Подпись и безопасность

- Токены GitHub, ключи Supabase service_role и ключи Cloudflare Realtime SFU в приложение не попадают; `check-release.mjs post` проверяет `app-update.yml`.
- **Подпись манифеста (без сертификата).** CI подписывает `latest.yml` ключом Ed25519 из секрета `UPDATE_SIGNING_KEY`, публичные ключи закреплены
  в `package.json` (`updatePublicKeys`) и попадают внутрь приложения. Перед скачиванием приложение проверяет подпись версии, файлов, SHA-512, размера и описания:
  неподписанное или изменённое обновление отклоняется. Манифест содержит SHA-512, поэтому заменить установщик незаметно тоже нельзя.
- Это защищает от подмены файлов релиза, в том числе при утечке `RELEASES_GH_TOKEN`. Не защищает от полного захвата GitHub-аккаунта:
  злоумышленник сможет запустить подпись в CI. Снижают этот риск двухфакторная защита и Environment с подтверждением; надёжнее подписывать манифест на отдельном компьютере.
- **Смена ключа:** выпустите версию с новым ключом, добавленным в `updatePublicKeys` рядом со старым и подписанную старым, затем переключите секрет на новый.
  Если ключ утерян, установленным приложениям потребуется ручная установка новой версии.
- **Сертификат Windows** подпись манифеста не заменяет: без него SmartScreen предупреждает при первой установке. Поэтому релиз без сертификата собирается только при явной переменной `ALLOW_UNSIGNED_UPDATES=true`.
- С сертификатом electron-builder запишет издателя в `app-update.yml`, и приложение начнёт отклонять обновления с чужой подписью Windows.
  Установленные неподписанные версии примут первое подписанное обновление, проверку получат уже следующие.
  Издатель (`CN`) должен оставаться прежним: при смене имени выпустите промежуточную версию с обоими именами в `win.signtoolOptions.publisherName`.
- Варианты: Azure Artifact Signing (`win.azureSignOptions`) или OV/EV-сертификат. Для аппаратного токена нужен собственный runner или облачный HSM.
- Защитите канал: двухфакторная защита GitHub, токен только на один репозиторий, защита тегов `v*` (**Settings → Rules → Rulesets**),
  Environment с обязательным подтверждением для release.yml.

## 5а. Файлы и папки (бесплатный тариф)

Supabase Free: **файл до 50 МБ**, хранилище **1 ГБ на весь проект** (вместе с аватарками и баннерами), исходящий трафик **5 ГБ в месяц**.
Поэтому лимиты Realism Voice (таблица `public.app_limits`, меняются в SQL Editor):

| Лимит | Значение |
|---|---|
| Один файл / ZIP папки | 50 МБ (максимум тарифа Free) |
| Все вложения проекта | 700 МБ |
| Весь Storage проекта (все бакеты) | 900 МБ из 1 ГБ |
| Вложения одного пользователя | 150 МБ |
| Загрузки пользователя за сутки | 250 МБ |
| Незавершённые загрузки одного пользователя | 5 |
| Выданные скачивания пользователя за месяц | 1 ГБ |
| Выданные скачивания всех за месяц | 3,5 ГБ |

* Папка упаковывается в ZIP потоково (до 1 ГБ исходных данных, до 10 000 файлов); архив должен уложиться в 50 МБ.
  Символические ссылки и junction не открываются — за пределы выбранной папки выйти нельзя. Получатель скачивает папку
  распакованной с сохранением структуры; защита от zip-slip и zip-бомб.
* Загрузка — по протоколу TUS частями по 6 МБ с продолжением после обрыва, паузой и отменой. Файл не читается в память целиком.
* Путь загрузки выдаёт сервер (`reserve_attachment`) после проверки прав и квот. Фактический размер файла сверяется с резервом
  и квотами в политике INSERT на `storage.objects`: Supabase Storage после записи файла повторяет проверку политики от имени
  пользователя с реальным `metadata.size`. Второй рубеж — `validate_attachments` не прикрепит к сообщению файл больше резерва.
* Скачивание учитывается (`request_attachment_download`), ссылки временные (2 минуты, видео — 15). Бакет приватный, доступ — по RLS
  канала/переписки. **Это оценка, а не точный учёт трафика:** ссылкой можно воспользоваться повторно, пока она действует; кэш и
  частичная загрузка видео дают расхождения; публичные бакеты (аватарки, баннеры) не учитываются. Квоты снижают риск превысить
  бесплатный трафик, но не гарантируют этого — следите за Usage в панели Supabase.
* Перед применением миграции выполните `supabase/admin/attachments-preflight.sql` (только чтение): настройки бакетов и все политики
  `storage.objects` — лишняя разрешающая политика из панели обошла бы ограничения.
* Скачанные файлы получают отметку «из интернета» (SmartScreen проверит EXE); приложение само ничего не открывает,
  перед открытием исполняемых файлов — предупреждение.
* Брошенные загрузки (старше 2 часов, не прикреплённые к сообщению) удаляет клиент автора при следующем входе.
* Пока миграция не применена, приложение 1.1.0 работает по старым правилам: файлы до 25 МБ, без квот.

Совместимость: пока `enforce_reservations` и `enforce_download_grants` = `false`, версии 1.0.x продолжают работать с вложениями
по-старому; квоты объёма проверяются и для них (в политике Storage), а резервы и учёт скачиваний — нет. Когда все обновятся
до 1.1.x, включите оба флага (`supabase/admin/attachment-limits.sql`, шаг 3). Обновление существующей базы проверяет
`scripts/test-sql-upgrade.mjs` (часть `npm run test:sql`): сообщения, серверы, аккаунты и файлы не меняются.

Остаточные риски: автор может многократно скачивать свой ещё не прикреплённый к сообщению файл без учёта (это нужно, чтобы его
можно было удалить); параллельные загрузки разных людей могут превысить общий лимит максимум на несколько файлов по 50 МБ.

**Больше 50 МБ:** нужен платный тариф (Supabase Pro — от $25/мес, файлы до 500 ГБ, 100 ГБ хранилища и 250 ГБ трафика включены)
или стороннее хранилище. Код к этому готов: достаточно поднять `attachment_max_bytes` и лимит бакета.

## 6. Архитектура и безопасность

```
electron/        main-процесс, preload, шифрованное хранилище сессии, PTT, настройки
src/             интерфейс (React), stores (Zustand), lib (Supabase, Realtime, клиент Cloudflare Realtime SFU)
supabase/        migrations/*.sql, setup.sql, functions/voice-sfu (и прежняя livekit-token)
scripts/         генерация иконок, склейка SQL, тест RLS
```

**Electron:** `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`; узкий preload API; каждый IPC-вызов проверяет,
что он пришёл из главного фрейма приложения; строгий CSP (`script-src 'self'`); приложение загружается через собственный
протокол `app://rv` (не `file://`); внешние ссылки — только http(s) в системном браузере; навигация и новые окна запрещены;
разрешения (микрофон, камера, экран, уведомления) выдаются только своему origin.

**Сессия:** токены Supabase шифруются через `safeStorage` (Windows DPAPI) в main-процессе и не лежат в `localStorage`.

**База данных:** все права проверяются в PostgreSQL:
- чужие ЛС недоступны (RLS по участникам переписки; вложения ЛС — в приватном бакете, по подписанным ссылкам);
- значки Owner и Tester (`profiles.badge`) привязаны к аккаунту и меняются только через SQL Editor или service_role: клиенту колонка недоступна, дополнительно это проверяет триггер, а второй Owner запрещён уникальным индексом;
- роли меняются только через `set_member_role` с проверкой старшинства — прямых UPDATE/INSERT для участников нет;
- редактирование только своих сообщений (`edit_message`), удаление — автор или модератор старше автора;
- приватные каналы: чтение/запись/вложения/голос — только по роли или явному списку участников;
- антиспам: лимиты на сообщения (8 за 10 с, 120 за 5 мин), приглашения (20/час), заявки в друзья (30/час),
  новые переписки (30/час), серверы (10/сутки), медленный режим каналов;
- Realtime: postgres_changes фильтруются RLS, приватные каналы набора текста / presence — политиками `realtime.messages`.

**Голос:** Edge Function `voice-sfu` проверяет JWT, членство на сервере, доступ к приватному каналу и право говорить
при входе и при каждой публикации и подписке; сессии SFU подписаны (HMAC) — чужими сессиями управлять нельзя,
а подписаться можно только на треки своей комнаты.

## 7. Известные ограничения

- Звук при демонстрации экрана — это весь системный звук Windows (Chromium не умеет захватывать звук отдельного окна).
- Глобальный Push-to-Talk использует нативный модуль `uiohook-napi`; перехват клавиш включается только во время голосового подключения в режиме PTT. Если модуль недоступен, PTT работает при активном окне.
- Звонки в ЛС — один на один. Групповые ЛС не реализованы.
- Автообновление начинает работать после настройки репозитория релизов (раздел 4а); пока он не указан, приложение честно показывает, что канал не настроен.
- Удаление аккаунта требует серверных полномочий и пока не реализовано в интерфейсе.
